# Registration boundary migration

Dependency parameter annotations remain the single source of dependency
declarations. The key tuples below select overrides; they do not repeat a
factory's dependency list. Forward references remain supported until `.end()`.

## Introduce and replace

Previously `.add()` could replace existing registrations:

```ts
const builder = DiBag.begin().add({ clock: () => 42 });
const changed = builder.add({ clock: () => 7 });
```

Use an explicit singleton key for replacement:

```ts
const builder = DiBag.begin().add({ clock: () => 42 });
const changed = builder.replace('clock', () => 7);
```

`.add()` now introduces new keys only. Visible duplicates fail type checking;
all actual own duplicates, including keys hidden by structural narrowing, throw
at runtime before a new builder is produced. A hidden newly introduced key
also cannot be overwritten by a subsequent `.add()`. Builders stay immutable.

`.replace()` accepts one existing string literal, rejecting widened strings,
union values, and open template keys. It checks every known consumer in the
resulting graph. The replacement may change the provided type when those
consumers remain compatible; missing forward providers are checked at `.end()`.

## Select fork overrides

Before:

```ts
const child = bag.fork({ clock: () => 7, stores: () => scopedStores });
const fresh = bag.fork({});
```

After:

```ts
const child = bag.fork(['clock', 'stores'], {
  clock: () => 7,
  stores: () => scopedStores,
});
const fresh = bag.fork();
```

Only selected keys participate in validation, result types, and runtime writes.
Every selected key must already exist and be an own property of the override
object. Extra properties are ignored without reading getters. Overrides must
preserve the original service contract, including exact Promise-valued edges.

TypeScript permits a structurally narrowed object to contain extra runtime
properties. The old one-map overload applied those properties without checking
them and has been removed. Use an inline tuple or a separately declared
`as const` tuple. Widened arrays, variadic or optional tuples, union-valued
elements, and open template elements cannot establish an exact selection.

Forks still create independent instances and own their own acquisitions.
Explicit root borrowing stays explicit: `source: () => root.resolve('source')`.
A shared instance retains its original dependencies. Close child bags and root
bags separately according to application ownership.

## Keep disposal handles intact

Before, a spread could accidentally sever the factory/disposer relationship:

```ts
const owned = DiBag.withDisposal(() => 42, value => { value.toFixed(); });
const invalid = { ...owned, create: () => 'wrong' };
```

Handles are now frozen and nominal; copies are rejected statically and at
runtime. Create a new pair instead:

```ts
const owned = DiBag.withDisposal(() => 'ready', value => { value.toUpperCase(); });
```

The readonly `create` property retains the exact factory type. Disposer metadata
is private, and async disposers continue to receive fulfilled factory values.
Ordinary factories remain borrowed even when their values have cleanup methods.

Acquisition includes successful inspection of the result's `then` property and
observer setup. Previously, an exception at either step could leave a cached
result that bypassed retry and had no cleanup. Such exceptions now preserve the
original error and retire the failed cache entry. Retirement abandons incoming
edges from callers that failed with that attempt. Accepted outgoing dependencies,
pending work, and ownership remain attached to the retired attempt so ordered
cleanup can still release them. A later resolution retries the factory.

Each retry now has a distinct acquisition identity. If A catches a failure from
B and succeeds, A's recorded dependency remains tied to the failed B attempt.
A later B attempt can read cached A without inheriting a false cycle. Genuine
synchronous and post-await dependency cycles still report their readable paths.
Factories preserve exact synchronous values and original Promise identities.

An ordinary object with a throwing `then` getter cannot be distinguished at
runtime from a PromiseLike with a throwing getter. Ownership therefore begins
only after successful synchronous classification or native Promise fulfillment;
malformed/unobservable values do not transfer ownership. Factories must retain
responsibility for those resources. Invoking the existing fulfilled-value
disposer on a raw thenable would pass the wrong argument type. No explicit
raw/synchronous acquisition adapter is introduced by this correction.

## Convert structural thenables explicitly

Automatic async tracking now requires genuine native Promise state. Previously,
the bag called `Promise.resolve` internally, which could invoke a native Promise
subclass's overridden `then` and transfer ownership of a substituted resource.
The bag now observes native state directly, including across realms, and preserves
the factory's exact returned Promise identity. It does not use `instanceof`,
reflection tags, or a caught `TypeError` as a native-brand classifier.

A raw structural thenable now fails native observation at resolution time.
Its `then` is not invoked, no ownership transfers, and the failed attempt is
evicted. This also applies to ordinary factories returning raw thenables.
Migrate factories that adapt structural implementations using standard conversion:

```ts
// Before: automatic structural assimilation.
const before = DiBag.withDisposal(() => legacyThenable, resource => resource.close());

// After: the factory explicitly returns a native Promise.
const after = DiBag.withDisposal(
  () => Promise.resolve(legacyThenable),
  resource => resource.close(),
);
// An async factory is another standard conversion boundary.
const asynchronous = DiBag.withDisposal(async () => legacyThenable, resource => resource.close());
```

The converted factory exposes `Promise<Awaited<typeof legacyThenable>>`; the bag
returns that exact native Promise and its disposer receives the fulfilled value.
Standard conversion still accepts fulfillment before a subsequent throw and
propagates rejection so later resolution can retry. Structural TypeScript types
cannot prove native Promise branding, so this boundary is checked at runtime.

Native observation can fail while reading `then`, `constructor`, or
`Symbol.species`, or while constructing the observer result. Those original
errors, including `TypeError`, still cause rollback with no raw-value disposal;
they are never interpreted as a signal to attempt structural assimilation.
The bag drains a separate native pending barrier and never consumes the observer's
customizable species result. Ordinary synchronous values and exact dependency
types are unchanged. No new helper, host-specific import, or configuration is needed.

## Preserve ownership through service projections

Use `DiBag.mapSync(registration, project)` when the projector needs the exact raw
source, including its Promise identity. Its output is exactly the projector's
return value. Use `DiBag.mapAsync(registration, project)` to explicitly await the
source and recursively await the projector result. It always returns a
Promise-valued provider, and source/projector throws become rejections.
Both helpers retain dependency requirements and static metadata.

`withDisposal(provider, dispose)` adds ownership of the provider's fulfilled
output while retaining all previous ownership stages. A projection no longer
requires rebuilding a factory and risking loss of its source disposer:

```ts
const raw = DiBag.withDisposal(openConnection, connection => connection.close());
const client = DiBag.withDisposal(
  DiBag.mapAsync(raw, connection => makeClient(connection)),
  client => client.close(),
);
```

The client closes before its original connection, regardless of fulfillment
order. Two explicit ownership operations on the same object mean two finalizer
calls. The original `withDisposal(create, dispose)` overload still exposes the
exact readonly `create` callback. Provider overloads return opaque handles.
Both disposal overloads now reject callbacks that declare a required non-void
`this`, matching receiver-free runtime invocation. Bind such methods explicitly
or wrap them in a closure; the factory's `create` and return types are unchanged.

Projection failures evict only their own attempt and preserve the boundary error.
Accepted stages are cleaned without releasing separately cached dependencies.
Synchronous resolution failures do not wait for asynchronous cleanup; pending
source ownership remains tracked and is released if it arrives later. Retrying
creates a separate attempt and cannot be evicted by the old source's completion.
`close()` drains all such work, then reports cleanup failures in invocation order
even if retired attempts' cleanup rejects in the opposite order.
Accepted stages are released only after that attempt's pending source and
projectors finish; a running projector may still be using an owned value after
an outer synchronous projection fails. Nonsettling work therefore retains the
attempt's owned stages and keeps close pending.

A ready synchronous projection of an unawaited Promise remains cached when that
raw Promise rejects. A genuinely pending source may finish dependency reads
during close even if its projection is already ready or failed. Completed source
proxies cannot borrow a pending projection's or another retry's permission.
Automatic source observation still requires a native Promise; adapt structural
source thenables inside the factory as described above. The explicit async
projector boundary uses standard awaiting semantics for its result.

## Handle all shutdown failures

Previously `close()` rejected with the first cleanup cause. It now attempts every
accepted finalizer and rejects with one `DiBagCleanupError`, even for a single
failure. Migrate cause checks and logging to its structured failure collection:

```ts
import { DiBagCleanupError } from 'di-bag';

try {
  await bag.close();
} catch (error) {
  if (!(error instanceof DiBagCleanupError)) throw error;
  for (const failure of error.failures) {
    console.error(failure.label, failure.acquisitionId, failure.bindingId, failure.error);
  }
}
```

`failures` is a readonly, frozen snapshot of frozen records. Each includes symbol
acquisition and binding IDs, a diagnostic label, and its original unknown cause.
The inherited `AggregateError.errors` lists those same original causes in cleanup
attempt order, preserving identity and thrown `undefined`. Application shutdown
loops should retain each bag's aggregate so scope diagnostics remain available.

`close()` is still a barrier: it stops public resolution and forking immediately,
drains pending factories and dependencies discovered after `await`, and disposes
dependents before dependencies, including through borrowed intermediaries.
Every call returns the identical Promise, including after rejection or from a
disposer. Cleanup runs once and the bag stays closed after failure. A disposer
must not await the scope-close Promise whose completion requires that disposer;
arbitrary user-created Promise cycles cannot be forcibly completed. Acquisition
failures remain on their resolution Promises and do not become cleanup failures.

## Receiver and construction boundaries

Factories run without a receiver and cannot require a non-void `this`. Bind a
receiver explicitly or use a closure when adapting an instance method. Returned
service methods may still use their own `this` normally.

Import `Bag` as a type for annotations. Construct bags with
`DiBag.begin().add(...).end()` or `.fork(...)`; the source and package no longer
expose an unchecked `Bag` constructor.

## Seal and install named modules

Use `DiBag.module().add(...).exports(['publicName'])` for reusable open graphs,
then `builder.install(module)` to compose them. Module builders support the same
checked `add` and singleton `replace`; they cannot resolve services. Explicit
export tuples use the same finite singleton-element rules as fork selections.
Only selected exports enter the host's public namespace. Every other local
provider has a fresh private identity for each installation, including repeated
installations of the same module.

All local providers contribute external requirements, even unexported or
currently unreachable ones. Later host registrations and modules may supply
them before `.end()`. Compatible host replacements and fork overrides of an
export remain visible to private module consumers, whose requirements continue
to be checked. Forks acquire and own a fresh graph, including private providers;
they do not inherit a parent's cached instances or cleanup ownership.

Rename public exports explicitly before repeated installation:
`feature.rename('service', 'otherService')`. Rename all colliding exports. The
factory's original parameter names remain valid; unrelated external names and
private names retain their meaning. A renamed export may use a private local
name without merging their identities. Duplicate installations fail atomically.

Import `Module`, `ModuleProvides`, and `ModuleRequires` as types. The latter two
are readonly contract views; they are not descriptors from which module values
can be reconstructed. Modules and their retained consumer constraints are
invariant. In particular, external requirements alone cannot describe private
consumers of replaceable exports. Inferred modules retain an additional
constraint parameter, and installations carry it through builders and bags.

Use `typeof feature`, `typeof installedBag`, or a factory function's `ReturnType`
to preserve inferred annotations. `Module<Provides, Requires>` defaults its third
constraint parameter to empty, and `Bag<Registrations>` defaults its second to
empty. Neither annotation can discard a nonempty installed contract. Ordinary
graphs with no installed constraints continue to support plain `Bag<R>`.
The runtime still rejects cloned, spread, and forged module values. No public
unchecked module constructor or mutable registry is exposed.

Run `bun run examples/modules.ts` for two modules with forward requirements,
an exported-service fork override, and owned private connection cleanup.

## Adopt typed tokens where identity must be explicit

Named dependencies remain unchanged: one finite object parameter declares names
and service shapes. A typed dependency uses a canonical caller-owned key and an
explicit positional selection instead:

```ts
export const clockKey = Symbol('clock');
export const clock = DiBag.token(clockKey).of<{ now(): number }>();

const stamp = DiBag.fromTokens([clock], selected => selected.now());
const bag = DiBag.begin().bind(clock, () => ({ now: () => 42 }))
  .add({ stamp }).end();
```

Keep both the `const` symbol and token exported from the contract-owning module.
Token identity is invariant in the symbol and service: the same key rewrapped
with the same service is compatible, while a wider or narrower redeclaration is
not. Inline or widened symbols cannot establish singleton identity. Distinct
`Symbol('clock')` values remain independent; repeated `Symbol.for('clock')`
returns the same runtime key and duplicate bindings therefore collide.

`fromTokens` requires a finite tuple of individually known tokens and passes
their services positionally without awaiting. Synchronous factories and
callbacks stay synchronous. A Promise-valued service keeps its exact type and
raw Promise identity; introduce awaiting only at an explicit async boundary.
Binding an existing provider retains its named/token requirements, metadata,
inspection frames, and disposal stages. The provider is reusable, but every
binding remains its own lazy cache slot unless its factory explicitly returns a
shared instance.

Module token rules mirror the named rules. A locally bound, unexported token is
private and fresh per installation. Exporting it creates a public slot. Selecting
an unbound token creates an external requirement that must be supplied by the
host before `.end()`. Public token overrides use a selected token tuple and a
computed own property:

```ts
const child = bag.fork([clock], { [clockKey]: () => ({ now: () => 7 }) });
```

The override reaches private module consumers of that public token. Root and
child bags retain independent acquisition and ownership state and must both be
closed. See `examples/tokens.ts` for the runnable migration shape.

`Provider<F, M, A, G>` adds an invariant fourth graph contract. Its default is an
empty token graph, preserving shorter annotations for genuinely token-free
providers; it cannot erase a provider with nonempty or opaque token requirements.
`Module<P, R, C, D>` remains four-parameter: `C` carries named/token consumer
constraints and `D` carries public registrations, including metadata, frames,
and bound-token contracts. Preserve inferred values with `typeof` or
`ReturnType`. `Binding`, `TokenGraph`, `From`, `Provided`, and `PublicProviders`
are type-only root exports so inferred package-author declarations can name the
retained contracts portably.

Runtime checks authenticate handles and reject missing or duplicate symbol keys,
but casts, unchecked JavaScript, erased carriers, and dynamically unknown plugin
graphs are not compile-time proofs. Typed tokens are an additional declaration
style, not a universal replacement for names. This increment does not complete
lifetime, startup/cancellation, or extension work.

## Retain provider metadata in annotations

Use `DiBag.withMetadata(registration, metadata)` to add immutable static metadata
without invoking a factory or changing its exact service, dependency, or ownership
contracts. Existing ordinary factories and `withDisposal` calls continue to work.
Wrap an owned registration directly to preserve its disposer:

```ts
const service = DiBag.withMetadata(
  DiBag.withDisposal(() => openConnection(), connection => connection.close()),
  { 'app:owner': { team: 'platform' } },
);
```

The metadata record is copied and frozen; payload objects keep their identity and
remain mutable. Application-chosen strings and unique symbols are supported; no
punctuation convention is enforced. Numeric and nonfinite key types are rejected.
Additional metadata calls must introduce new keys. Runtime preflight checks every
own key, including hidden keys, for collisions before reading any metadata getter.
Keep the returned provider handle intact; spreading does not retain its provenance.

`bag.inspect(key)` returns a frozen snapshot without resolving that key. Static
`metadata`, `bindingId`, and `label` remain available after close. `acquisitions`
contains copied attempt identities, states, and ordered metadata-presence tuples;
it contains no service values and is empty before acquisition and after close.
Existing providers have empty frame tuples. Earlier snapshots never change, and
failed attempts are removed rather than retained as a history.

`Module<P, R, C, D>` now retains public registration metadata in `D`, separately
from the consumer constraints in `C`. Exporting and renaming a provider preserves
its metadata and frames while keeping private requirements out of its synthetic
public factory contract. `ModuleProvides` and `ModuleRequires` still expose the
same readonly service/requirement views. Use `typeof feature` or `ReturnType` for
annotations carrying metadata; defaults in shorter `Module` annotations cannot
erase nonempty metadata/frame contracts. Empty metadata/frame modules retain
the previous annotation behavior. An explicitly erased registration cannot prove
graph closure; preserve its inferred provider type instead.

## Select optional box boundaries explicitly

Use `di-bag/sas-box` for `fromSasBox(registration, { mode })`, with mandatory
`sync`, `async`, or `sync-first`. Sync preserves the immediate raw result;
asynchronous modes await the box and selected result. `sync-first` needs a
required complete `sync` field; a missing/optional narrowed view must use
explicit `async` instead. An undefined-capable sync field requires an async
fallback. Selected methods must accept zero ordinary arguments and their box
receiver. The adapters neither import nor install the box libraries.

Use `di-bag/val-box` for `fromValBox` (immediate) or `fromValBoxAsync` (awaited,
always Promise). Both call the structural `snapshot()` once per acquisition.
Default required mode throws for an absent value. Select `{ value: 'presence' }`
for `Presence<T>`, which retains present-undefined. Supplied options must specify
the value mode; an empty options object is not a mode selection.

For context-sensitive factories returning nested methods, declare the factory
before calling the val adapter. The same unannotated function body retains
exact payload, dependency and frame types once predeclared; the equivalent
nested inline method form can currently report an invalid snapshot capability.
This bounded inference limitation is retained for the dedicated inference work.

Val adapters append ordered `ValBoxFrame<M>` acquisition metadata, containing
metadata presence and string/null alias. Every declared frame starts absent at
attempt creation and becomes present when its adapter completes. The snapshot
records and inspection tuple are copied/frozen, while payloads retain identity.
Import `ValBoxFrame` as a type from the root or adapter subpath. Root imports
do not load adapter runtime code. Preserve provider generics (or `typeof`) in
annotations so acquired frame types cannot be erased.

Ownership remains explicit: `fromValBox(DiBag.withDisposal(openBox, closeBox))`
disposes only the raw box. Add outer `DiBag.withDisposal` only when the bag also
owns the payload. Outer disposal runs before raw disposal. Failed snapshots
retire acquired ownership, and a pending source keeps permission to finish its
own work during closure. A caller that catches an exposed acquisition failure
does not retain a successful dependency edge to that failed attempt; the attempt
still retains its own pending work and dependencies for cleanup.
