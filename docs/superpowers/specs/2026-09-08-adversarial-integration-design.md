# Adversarial cross-feature integration design

This increment makes the final DI Bag interaction contract executable. It does not add an API, change a public semantic, access a network service, or publish a package. It composes real `sas-box` and `val-box` 0.1.0 fixture archives with the public DI Bag package and verifies that independent features retain one coherent acquisition, ownership, lifecycle, observer, declaration, and export model.

## Boundaries and implementation shape

Create one deterministic source-level oracle in `tests/final-adversarial-integration.test.ts` and one dependency-free runtime assertion string in `tests/final-adversarial-runtime-fixture.ts`. The source test imports the existing public source facade and real box fixtures. The runtime fixture is embedded in existing installed-package harnesses so the same JSON result is required from fresh DI Bag archives in Node CJS, Node ESM, and every existing Bun archive lane.

The fixture records reference-equality booleans; stable `scopeId`, `bindingId`, and `acquisitionId` relationships; disposer order; observer events and paired observer errors; exact plugin phase; cancellation cause; and effects that must not occur. It uses test-controlled deferred promises, never sleeps. Contractual serial order is an exact array; deliberately parallel startup compares named counts and membership.

`tests/final-adversarial-integration.test.ts` owns source matrix rows. `tests/box-package.test.ts` owns fixture hash, real-box/core-only installation, and root/subpath export checks. `tests/package.test.ts` owns the classic installed package. `tests/native-package.test.ts` owns classic6/native7 construction, source-deleted declarations, CJS/MJS consumers, and Node/Bun. The new fixture is called by all three package tests so source success cannot mask an export, emitter, declaration, loader, or archive regression.

The embedded string writes one `JSON.stringify(result)` line and throws an error containing violated matrix ID. Source tests import the exact expected literal. Package tests compare complete parsed value, never stdout prefix. Error tests capture thrown values and use `toBe(original)`.

Add `tests/types/final-adversarial-integration.ts`, its source-deleted consumer, and `tests/types/negative/final-adversarial-integration.ts`. Positive declarations use existing `Assert` and `Equal`; negative declarations use only unsuppressed `// diagnostic:` markers, with one invalid expression per marker region and disjoint selected/overridden/shared keys between regions. Register both fixture names in `tests/box-contract-fixtures.ts` for classic/native physical package compilers. No public interface is added solely for this suite.

## Failure policy

The increment first makes every matrix assertion red against unmodified implementation. A red proving a source defect is not repaired opportunistically: record matrix ID, minimal reproducer, original error/identity evidence, and implicated source file in a new bug-specific design before modifying runtime code. A red caused by incorrect test expectation is corrected in test with adjacent explanation of the documented contract. This preserves a reviewable distinction between discovering a regression and changing semantics.

## Non-goals

This does not reimplement individual feature suites, loosen native markers, add a runtime `sas-box`/`val-box` dependency, change exports, invoke network commands, query a registry, tag, push, log in, publish, or alter fixture archives. It uses fixed provenance in `tests/fixtures/box-packages/README.md`.
