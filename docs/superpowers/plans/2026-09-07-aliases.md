# Checked aliases implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Provide checked name/token aliases that preserve canonical target acquisition semantics.

**Architecture:** Immutable builder entries retain alias target contracts and lexical
routing. Runtime resolution follows the canonical target before creating attempts;
static graph and lifetime checks retain the alias dependency.

**Spec:** `docs/superpowers/specs/2026-09-07-aliases-design.md`.

## Global constraints

- An alias creates no acquisition, value cache, ownership or implicit awaiting.
- Every argument is one known name or genuine token; destinations are new.
- Module privacy, owner routing, cancellation and final readiness are preserved.
- Retain exact output, invariant history and declaration-only graph obligations.
- No relaxed native diagnostic allowances or compiler-work thresholds.
- This increment does not complete contributions, plugins, compiler or release work.
