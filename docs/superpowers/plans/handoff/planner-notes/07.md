# Scope notes: phase 6, plan file `docs/superpowers/plans/2026-09-21-07-container-renames.md`, spike S3

State on entry: phases 0 to 5 done. Builder methods have their 0.5.0 names (`withServices`, `buildContainer`, ...). The class returned by `buildContainer()` is still called `Bag`, with `resolve`, `inspect`, `inspectGraph`, `createScope`, `fork`, `close`, `ensureServicesReady`.

1. `Bag` becomes `Container`: the exported type name, the class, JSDoc, messages that say "bag is closed" (keep the codes), `BuildBag`-style helper names. Internal names such as `BagRuntime` may stay; decide and say why. The product name `DiBag`, the facade, the package name and the `DI_BAG_` prefix stay.
2. `inspect(key)` to `serviceSnapshot(serviceKey)`, `inspectGraph()` to `graphSnapshot()`.
3. `createScope()`, `createScope({ share })`, `createScope(keys, overrides, { share })` collapse into `createChildContainer(options?)` with one bag `{ replacedServiceKeys?, replacementProviders?, sharedParentServiceKeys? }` (S3). `fork()` and `fork(keys, overrides)` collapse into `createIndependentContainer(options?)` with `{ replacedServiceKeys?, replacementProviders? }`. The hard part is inference: `replacementProviders` must be contextually typed from `replacedServiceKeys` inside ONE object literal (today the tuple is a separate earlier argument precisely so that `K` is inferred before `O`; read the comments above `fork` in `src/di-bag.ts`). Prototype with `const` type parameters and property order; test inline tuples, `as const` tuples declared separately, token keys via `[token.key]` computed properties, collection tokens, and the negative cases in `tests/types/negative/` for fork and scopes. `selectScope` in `src/scope-selection.ts` and the fork parsing in `src/di-bag.ts` parse the new bag (own properties only, unknown keys rejected, snapshot by index). Types: `ScopeOptions` to `CreateChildContainerOptions`, new `CreateIndependentContainerOptions`; operation labels and `details.operation`. Fallback from the spec: the pair stays positional, followed by the bag: `createChildContainer(replacedServiceKeys, replacementProviders, { sharedParentServiceKeys }?)`.
4. `module.renameExport(oldKey, newKey)` to `module.withRenamedExport({ currentExportKey, newExportKey })`.
