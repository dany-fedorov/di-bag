# Scope notes: phase 8, plan file `docs/superpowers/plans/2026-09-21-09-provider-sources.md`, spike S4

State on entry: phases 0 to 7 done. Builder, container and module methods have their 0.5.0 names. The facade still has `fromFactory`, `fromSyncFactory`, `fromAsyncFactory`, `fromFunction`, `fromClass`, `fromPlugin`, `token(key).of<S>()` and `.forCollectionOf<Item>()`, `optional`, `lazy`, and the decorator functions `withDisposal`, `withLifetime`, `withMetadata`, `transformService` (those four change in phase 9, not here).

1. `DiBag.createProvider(factory, options?)` replaces `fromFactory`, `fromSyncFactory`, `fromAsyncFactory`. Options: `{ factoryReturnKind?: FactoryReturnKind; factoryReceivesContext?: true }`. `FactoryReturnKind = 'auto-detect' | 'sync-value' | 'native-promise' | 'uninspected'`. Mapping from today: `auto` is `'auto-detect'` (default), `raw` is `'uninspected'`, `nativePromise` is `'native-promise'`, `fromSyncFactory` is `'sync-value'` (a raw stage at run time plus the compile-time `SyncOutput` rejection of Promise and thenable outputs), `fromAsyncFactory` is `'native-promise'` with the compile-time `AsyncOutput` requirement (decide whether `'native-promise'` through the old `fromFactory` path, which used `NativeOutput`, merges into the same check; read `src/acquisition-mode.ts` and `src/acquisition-context.ts` and keep every guarantee). `context: 'acquisition'` becomes `factoryReceivesContext: true`. The type `AcquisitionMode` becomes `FactoryReturnKind`; `transformService`'s `acquisitionMode` option keeps its KEY until phase 9 but its VALUES change here, because they share the type. `BindingSnapshot.acquisitionMode` becomes `factoryReturnKind` with the new values. `classifierRequired()` and every compile-time message that says `fromSyncFactory`, `fromAsyncFactory`, `acquisitionMode raw` (`AutoOutput`, `SyncOutput`, `AsyncOutput`, `NativeOutput`, `ThenableAdmission` in `src/acquisition-mode.ts` and `src/types.ts`) are reworded with the new names; `docs/agent/errors.md` families `structural-thenable` and `portable-factory-output` follow. Runtime code names change only in phase 11.
2. `AcquisitionContext` becomes `FactoryContext`; its `signal` becomes `abortSignal`; `pushDisposer` and `DisposerContext` keep their names.
3. `DiBag.createProviderFromFunction({ dependencies, factoryFunction, factoryReturnKind?, factoryReceivesContext? })` replaces `fromFunction(tokens, callback, options?)` (S4). With `factoryReceivesContext: true` the `FactoryContext` is passed as the LAST argument after the dependencies; today positional sources cannot receive it at all (read `src/composition.ts`, `sourceDescription(..., contextual)` in `src/provider-operations.ts` and how `evaluate` passes the context in `src/provider-execution.ts`). `DiBag.createProviderFromClass({ dependencies, serviceClass, factoryReturnKind? })` replaces `fromClass`; classes never receive the context. `DiBag.createProviderFromPlugin({ dependencies, pluginDescriptor, isValidPluginOutput, factoryReturnKind })` replaces `fromPlugin`, with `factoryReturnKind` limited to `'uninspected' | 'native-promise'`; the plugin descriptor contract `{ apiVersion: 1, create, dispose? }` is unchanged. Types: `CompositionArguments` to `PositionalFactoryArguments`, `CompositionFunction` to `PositionalFactoryFunction`, `PluginAcquisitionMode` to `PluginReturnKind`, `PluginOptions` folded into the bag type (name it `CreateProviderFromPluginOptions`), `PluginProviderFactory` renamed to match. S4: the callback's parameters must be inferred from `dependencies` inside one object literal, including `optional`/`lazy` references, collection tokens, default parameters and rest parameters (read the comments in `src/composition.ts` about materializing the mapped tuple). Fallback from the spec: `createProviderFromFunction(dependencies, factoryFunction, options?)`, the pair positional followed by the bag; same for class.
4. Tokens: `DiBag.token(key).of<S>()` becomes `DiBag.createToken(symbol).forService<S>()`; `.forCollectionOf<Item>()` keeps its name; `token.key` becomes `token.symbol`; compile-time messages about token keys follow.
