# Scope notes: phase 9, plan file `docs/superpowers/plans/2026-09-21-10-provider-methods.md`, spike S2

State on entry: phases 0 to 8 done. `DiBag.createProvider(factory, options?)`, `createProviderFromFunction/Class/Plugin`, `FactoryReturnKind`, `FactoryContext`, `createToken` exist. The decorators are still facade functions: `DiBag.withDisposal(registration, dispose)`, `DiBag.withLifetime(registration, lifetime, { allowScopedDependencies }?)`, `DiBag.withMetadata(registration, { static?, dynamic?: { mode, describe } })`, `DiBag.transformService(registration, { mode, transform, acquisitionMode? })`. Lifetime values are still `'root' | 'scoped' | 'transient'` and the default is still scoped.

1. Decorators become methods on `Provider` (S2):
   - `provider.withDisposal(disposeService)`
   - `provider.withLifetime(lifetime, { allowsScopedDependencies }?)`
   - `provider.withRegistrationMetadata(registrationMetadata)`
   - `provider.withAcquisitionMetadata({ describeAcquisition, callbackReceives })`
   - `provider.withTransformedService({ transformService, callbackReceives, transformReturnKind? })`
   `callbackReceives` is `'exposed-service'` (was `mode: 'direct'`) or `'fulfilled-value'` (was `'awaited'`); `transformReturnKind` is a `FactoryReturnKind` and is rejected together with `'fulfilled-value'`, as `acquisitionMode` is rejected with `awaited` today. `withMetadata` with both `static` and `dynamic` becomes two chained calls in the order the current implementation applies them (static first; read `withMetadata` in `src/provider.ts`). A plain function has no methods, so it is wrapped with `DiBag.createProvider(factory)` first; a plain factory stays a valid registration value everywhere.
2. `Provider` today is a type-only class with no public constructor whose instances are frozen handles, with the description in a WeakMap (`src/provider.ts`, `src/provider-operations.ts`) and invariance carried by `declare readonly [providerInvariant]`. Methods must go on the class prototype (handles are frozen), keep every type-level contract that `transform`, `annotate`, `attachStaticMetadata`, `withLifetime` (in `src/lifetime.ts`), `withDisposal` (in `src/registration.ts`) and `withTokenBinding` produce today, and must not break declaration emit nameability or variance (study the comments about invariance and about `ProviderContext`). `FactoryWithDisposal` leaves the public surface: decide whether it survives internally; the zero-dependency fast path of `withReplacedService` names it in an overload today, so re-establish that fast path for `Provider` values produced by `createProvider(f).withDisposal(d)` and for plain factories, and measure. `Registration` becomes `ProviderOrFactory`. The four facade functions and their `DiBagApi` members are removed. Fallback from the spec when S2 fails: facade functions with bags, `DiBag.providerWithDisposal({ provider, disposeService })`, `providerWithLifetime({ provider, lifetime, allowsScopedDependencies? })`, `providerWithRegistrationMetadata({ provider, registrationMetadata })`, `providerWithAcquisitionMetadata({ provider, describeAcquisition, callbackReceives })`, `providerWithTransformedService({ provider, transformService, callbackReceives, transformReturnKind? })`, accepting plain factories; give the complete alternative task list.
3. Lifetime VALUES are renamed here (the default flips only in phase 10): `'root'` to `'singleton:one-per-container-tree'`, `'scoped'` to `'scoped:one-per-container'`, `'transient'` to `'transient:one-per-resolve'`. Only the full value is accepted: a bare `'scoped'` is a compile error and a runtime error whose message names the full value. Internal `LifetimePolicy.kind` may keep short internal names; decide and keep snapshots and events reporting the FULL value in their `lifetime` field. `allowScopedDependencies` becomes `allowsScopedDependencies`. The compile-time message family `root-capture` becomes `singleton-captures-scoped` here (anchor in `docs/agent/errors.md`, `SeeErrors<'root-capture'>`, message wording in `src/lifetime-types.ts`, the runtime message of `DI_BAG_LIFETIME_DEPENDENCY`), so phase 11 does not touch lifetimes again.

Codemod: a custom transform for the four facade decorators that uses the ORIGINAL type of the first argument: a function-typed argument becomes `<facade>.createProvider(<arg>).withX(...)` using the same facade expression the call used (a derived facade from `withConfiguration` must be kept), a provider-typed argument becomes `<arg>.withX(...)`, nested decorator calls compose into one chain, `withMetadata` splits, option keys and string values are renamed. Value renames for lifetimes everywhere they appear as arguments or in comparisons against `lifetime` fields.

Migrate tests (`tests/providers.test.ts`, `tests/lifetimes.test.ts`, `tests/disposal.test.ts`, `tests/acquisition-metadata.test.ts`, `tests/api-renaming.test.ts`, type fixtures), examples, generators, `tools/graph/lib/extract.mjs` (`WRAPPERS` reads decorator names and the lifetime literal today; it must read method chains and the new values, and keep the old forms), `scripts/agent-eval`, `AGENTS.md` rules 3 and 6, `docs/agent`, `api-card-tasks.json`.
