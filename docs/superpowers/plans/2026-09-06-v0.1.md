# di-bag v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a verified standalone v0.1 package with explicit async factories and optional disposal.

**Architecture:** Keep the lazy proxy-based builder and normalize ordinary and
disposable registrations internally. Validate the complete type-level graph,
record runtime dependency edges, and give each bag its own memo and lifecycle.
The type and runtime steps are tightly coupled and execute sequentially.

**Tech Stack:** TypeScript 5.9.3, Bun tests, npm packaging, zero runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-06-v0.1-design.md`

## Global Constraints

- Runtime has zero third-party dependencies and no platform-specific APIs.
- TypeScript 5.9.3 is the development compiler; strict checks are enabled.
- The optional lifecycle helper is `DiBag.withDisposal(create, dispose)`.
- Async edges are explicit promises; synchronous resolution stays synchronous.
- Preserve historical code in `docs/history/`; do not publish or push automatically.

## Task 2: Async graph tracking and lifecycle

**Interfaces:** `DiBag.withDisposal<F>(create: F, dispose:
(value: Awaited<ReturnType<F>>) => void | Promise<void>)` produces a branded

- [x] Write and run failing tests for async cycles across `await` and rejected
      factory retry. Capture the factory token in each proxy, record each read edge,
      and search for a return path before adding it. Cache the original promise;
      observe fulfillment/rejection separately to record ownership and evict errors.
- [x] Write and run a cleanup test before implementing `withDisposal`:

```ts
const closed: number[] = [];
const bag = DiBag.begin()
  .add({
    resource: DiBag.withDisposal(
      () => 42,
      (value) => {
        closed.push(value);
      },
    ),
  })
  .end();
expect(bag.resolve('resource')).toBe(42);
await bag.close();
expect(closed).toEqual([42]);
```

- [x] Add normalization for branded registrations; ordinary factory return
      objects shaped like `{ create, dispose }` remain ordinary service values.
      Add compile tests that infer both dependencies and awaited disposer values.
- [x] Test reverse order, dependency order across asynchronous completion,
      never-resolved and failed acquisition, async cleanup, thrown `undefined`,
      and continued cleanup after failure before implementing the close state machine.
- [x] Test close while factories are pending, late dependency reads, rejection,

      reversing it for sequential cleanup. Reject new public work immediately.
- [x] Run all runtime and compile fixtures; split registration and graph types

## Inline factory inference follow-up

- The user approved a bounded follow-up to support inline method-returning
  factories in `.add()` and `.fork()`, retaining dependency checks and leaving
  runtime/disposal behavior unchanged.
- Three new compile-positive fixtures first failed with the old broad generic
  constraint. The fix infers keys through a self-mapped registration constraint
  and separately requires `Registrations` on the argument. `Checked`, `Complete`,
  and `Overrides` are unchanged. Restoring either old generic constraint in an
  in-memory compiler check makes its corresponding fixture fail again.
- Review and local probes caught overly permissive map inputs in the initial
  self-mapped constraint. Four regressions first demonstrated acceptance of
  booleans, widened `object` registrations/overrides, and prototype-only class
  registrations. The argument guard restores their rejection. Independent
  re-review accepted the corrected implementation with no material findings.
- Exact-type assertions cover inline methods, forward dependencies, nested
  forks, returned methods using `this`, and async/disposable values. Thirteen
  new negative fixtures preserve input validation, missing dependency errors,
  dependency shape checks, replacement checks, and fork restrictions.
- The WBS example now declares its work-item factory inline. README's workaround
  warning is removed, and emitted-declaration consumers exercise inline methods
  through both CommonJS and ESM package imports.
- Final verification: `npm run check` exited 0 with **73 tests passing**, strict
  checking, and build. `npm run example:wbs` and the package dry run exited 0;
